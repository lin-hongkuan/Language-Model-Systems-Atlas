## 预训练为什么有用？

监督任务的数据通常比较少，而且每种任务都要单独收集标签。互联网上的大量文本本身没有人工标注，却含有丰富的共现、句法和事实线索。预训练把“根据文本的一部分预测另一部分”当作监督任务，先让模型学习通用表示，再用下游数据调整它。

这里的“自监督”不是没有目标，而是目标标签由原始文本自动构造。例如，句子中下一个 token、被遮住的词，都是训练信号。预训练学到的是训练目标与数据分布下有用的规律；它不保证每个记住的关联都真实，也不能消除数据的偏差。

### 从“自己出题”到“学通用表示”

想象我们有数十亿句子，却没有人为每句标注情感、实体或问答答案。下一词预测仍能出题：给模型前缀“今天外面下着”，让原文后面的“雨”作为答案。模型在许多上下文中反复练习，会学到搭配、句法和某些事实关联。这里的监督是**预测任务的监督**，不是人工担保文本真假。

预训练之后，同一套表示可适配到多个下游任务；但迁移效果取决于模型结构、数据和目标，不能由“预训练损失降低”直接推出“所有任务都会变好”。

## 三种常见的预训练目标

### 1. 因果语言模型：预测下一个 token

自回归模型按从左到右的条件概率分解序列：

$$
P_\theta(x_1,\ldots,x_T)
=\prod_{t=1}^{T}P_\theta(x_t\mid x_{<t}).
$$

如果在序列前加开始符号 BOS，模型可以用 BOS 预测第一个真实 token，再逐位置预测后续 token。约定 $x_0=\mathrm{BOS}$，包含这个边界位置时，序列损失写作：

$$
\mathcal{L}_{\text{CLM}}
=-\sum_{t=1}^{T}\log P_\theta(x_t\mid x_0,x_{<t}).
$$

下面的张量例子暂不加入 BOS，因此只计算从已有 token 预测下一个 token 的 $T-1$ 个位置，目标为 $x_2,\ldots,x_T$；这种写法不训练对第一个 token $x_1$ 的预测。若加入 BOS，则可将 $x_1,\ldots,x_T$ 全部作为目标。

例如文本 token 为「猫、吃、鱼」，输入位置「猫、吃」分别监督目标「吃、鱼」。模型在训练中看不到目标位置之后的 token；因此它可以直接用同一目标逐 token 生成文本。

设原始 token 批次为 $X\in\mathbb{N}^{B\times T}$，且不加入 BOS。先用 `X[:, :-1]` 作为模型输入、`X[:, 1:]` 作为目标；二者 shape 都是 $[B,T-1]$。模型输出 logits 为 $[B,T-1,V]$，其中 $V$ 是词表大小。若要用 BOS 预测原序列的全部 $T$ 个 token，则输入为 `[BOS]` 与 `X[:, :-1]` 拼接，目标为 $X$；模型输入、目标和 logits 的时间长度都是 $T$，shape 分别为 $[B,T]$、$[B,T]$ 和 $[B,T,V]$。两种情况下都要用因果遮罩挡住未来位置。

### 形状与标签：把公式落到一小批数据

假设 tokenizer 把一句话编码为 ID `[17, 8, 29, 4]`。训练时，当前位置读到的前缀和正确答案错开一位：

| 位置 | 输入 $x$ | 目标 $y$ | 模型要预测 |
|---:|---:|---:|---|
| 0 | 17 | 8 | ID 8 |
| 1 | 8 | 29 | ID 29 |
| 2 | 29 | 4 | ID 4 |

若原始 batch 的 `LongTensor` 形状为 `[B,T]`，不加 BOS 时，切片后的模型输入和目标都是 `[B,T-1]`。Embedding 后模型输入通常为浮点张量 `[B,T-1,d]`；每个位置给词表 $V$ 个候选打分，logits 是 `[B,T-1,V]`；目标仍是整数类别 ID `[B,T-1]`，不需要手工做 one-hot。PyTorch 的交叉熵接口要求类别轴符合函数约定，实践中常把 logits reshape/转置成二维批量分类问题来算。

**两个常见错位错误：**若位置 $t$ 的目标仍是同一个 $x_t$，模型可能只学会复制已见 token；若因果注意力没有屏蔽右侧，模型训练时能偷看答案。padding 位置通常要通过 `ignore_index` 排除。损失按有效 token 求和还是取平均会影响梯度尺度，比较实验时必须保持定义一致。

真实 token 概率越高，单 token 负对数损失越小：若正确 token 概率为 $0.8$，$-\ln(0.8)\approx0.223$；若为 $0.1$，损失为 $-\ln(0.1)\approx2.303$。这说明目标函数惩罚的是给正确答案分配过低概率。

### 2. 掩码语言模型：恢复被遮住的内容

双向编码器希望一个位置能同时使用左、右上下文。若训练目标是预测每个位置的下一个 token，模型就不能在生成时直接访问未来而又声称使用了双向上下文。掩码语言模型改为随机选取一组位置 $M$，将这些输入位置替换或扰动，再只在被选位置上预测原 token：

$$
\mathcal{L}_{\text{MLM}}
=-\sum_{i\in M}
\log P_\theta(x_i\mid \widetilde{x}_{1:T}),
$$

其中 $\widetilde{x}$ 表示经过遮蔽或替换的输入。被预测的位置仍可以读取两侧未被遮住的上下文，因此适合训练双向表示。

例子：原句「小猫在窗边睡觉」，输入可能变成「小猫在 [MASK] 睡觉」，模型预测被替换的位置。实际训练会采用更丰富的遮蔽策略，避免模型只学会识别单一的 [MASK] 符号。

### 3. Encoder–decoder：把输入改写成目标序列

编码器读取完整输入，解码器依据输入表示和已生成的目标前缀预测目标 token。目标可以是翻译，也可以是从输入中挖去若干连续片段后，让解码器按顺序重建这些片段。后者称为 span corruption。

这种设计统一了“读入一段内容”和“生成另一段内容”：编码器提供源上下文，解码器用自回归目标逐 token 生成答案。它适合输入与输出都具有序列结构的任务。

## 一个小例子：同一段文本，不同监督任务

原文是“春天 花 开了”：

| 目标 | 模型读到的内容 | 要预测什么 |
|---|---|---|
| 因果语言模型 | 春天 花 | 下一 token 开了 |
| 掩码语言模型 | 春天 [MASK] 开了 | 被遮住的 花 |
| Span corruption | 输入中移除一段并放置占位符 | 解码器生成被移除的完整片段 |

差别不是“哪一种模型更懂语言”，而是训练时允许读取的上下文、预测目标与架构安排不同。一个目标学到的能力也受数据和训练方式影响。

## 子词与开放词表

纯词级词表会遇到新名字、拼写变化和罕见词。若每种罕见形式都占一个独立词表项，词表会膨胀；若未见词统统变成 [UNK]，模型又失去词内信息。

子词方法把常见词保留成较大的片段，把少见词拆成更小单元。BPE 的基本思路是：从字符或字节单元开始，统计相邻 token 对的频率，反复合并高频 pair，并把合并顺序保存下来供编码时使用。

一个玩具语料包含 abab 和 abac。若当前最常见相邻 pair 是 a b，合并后可得到 ab ab 与 ab a c。真实实现还需处理词边界、特殊 token、Unicode 字节和并列频率等细节。

## 数据、规模与系统：目标之外的三条主线

课程标题还包含 Scaling、Systems、Data。理解预训练不能只看损失公式：数据决定模型见到了什么，规模决定训练预算如何分配，系统决定给定预算能否有效完成计算。

### 一条常见的数据准备链

```text
原始语料 → 来源/许可检查 → 规范化和去重 → 质量筛选
         → 语言与领域配比 → tokenizer 编码和打包 → 训练及留出评测
```

- **精确与近似去重：**复制网页会让重复内容被过度加权；去重规则太激进又可能误删高价值的常见知识。
- **数据污染：**若评测题或答案已经在训练语料里，测试分数可能反映记忆。训练集和评测集需要做重叠审计。
- **混合配比：**语言、领域和文体的比例会改变覆盖面；清洗规则也可能系统性移除某些社群的表达。
- **数据版本：**保留来源、过滤步骤和快照，才能复现实验、追查错误和响应删除请求。

不存在一个代表所有目标的“数据干净分”。筛选太松会带进垃圾和重复；筛选太严可能把口语、方言、少数语言或专业资料误删。要结合下游能力和各子群的评估判断。

### 规模估算：参数量乘训练 token 数

稠密 Transformer 的训练计算量常用 $C\propto ND$ 作数量级估计，$N$ 是参数数，$D$ 是训练 token 数。经典粗略近似会写成 $C\approx6ND$；结构、序列长度、激活重算和具体 kernel 会改变常数，所以预算估算后仍要 profile。

例如 $N=7\times10^9$ 个参数、$D=2\times10^{12}$ 个 token，得到 $6ND\approx8.4\times10^{22}$ FLOPs。若参数量加倍而 token 数不变，粗略计算量也约加倍；但能力不会因此保证等比例增加。数据重复、质量、模型/数据配比和下游任务都可能成为瓶颈。

### 系统效率词汇

- **吞吐量（tokens/s）：**每秒完成多少训练 token。
- **MFU（Model FLOPs Utilization）：**实际模型计算吞吐与硬件理论峰值的近似比率，用于诊断设备有没有被有效利用；它不是质量指标。
- **数据并行：**多台设备处理不同样本并同步梯度。它能增加吞吐，但同步通信和较大的全局 batch 会影响速度与训练动态。
- **张量并行/流水线并行：**把单个模型的矩阵计算或网络层分配到多台设备，可容纳更大模型，也带来通信和调度开销。
- **激活重算：**不保留部分中间值、反向时重新计算，以额外 FLOPs 换取较低显存。

若设备一直等待读数据、网络通信占满时间或大量 token 被 padding 浪费，理论 FLOPs 不能代表实际有效训练。预训练因此同时是统计学习与分布式系统问题。

## 预训练的边界

- **预训练损失不是事实正确率。** 模型被训练去拟合文本概率，文本中的错误与偏见也可能被学到。
- **编码器和自回归解码器的目标不同。** 双向 MLM 表示很有用，但生成任意长文本时通常需要额外设计。
- **“无标签”并非“无选择”。** 语料来源、清洗规则、tokenizer、遮蔽方式和训练预算都会影响模型学到什么。
- **更大的训练规模不自动带来目标能力。** 需要结合任务评测、数据质量、训练动态和使用成本判断。
- **词表策略会影响后续计算。** 相同文字可能被不同 tokenizer 切成不同数量的 token，改变上下文长度和按 token 计的损失。

## 分层练习：从目标函数到训练审查

### 入门：看清条件前缀

给定 token `[猫, 吃, 鱼]`，因果模型在预测“吃”时能读到什么？预测“鱼”时能读到什么？

<details><summary>提示</summary>把目标位置右侧的真实 token 暂时盖住。</details>

### 进阶：核对张量

若原始 `tokens.shape == [8,512]`、词表 $V=32000$，并按本页不加 BOS 的方式右移构造模型输入与目标，`input_ids`、logits 和目标标签各是什么形状？有效标签总数为什么不能只从形状推断？

<details><summary>提示</summary>每个位置对所有词表项打分；padding 位置可能被忽略。</details>

### 专业视角：判断规模实验

实验 A 的训练损失更低，但网页去重没做、训练 token 更多；实验 B 的训练较少但语料干净，评测集也比训练语料新。能否宣布 A 的通用能力一定更好？设计一个更公平的比较方案。

<details><summary>提示</summary>训练目标、评测污染、计算预算与任务表现要分开控制。</details>

<details>
<summary>核对答案</summary>

- 入门：预测“吃”只能用前缀“猫”；预测“鱼”可用“猫、吃”。两者都不能看到目标之后的 token。
- 进阶：`input_ids` 与标签都是 `[8,511]`，logits 是 `[8,511,32000]`。有效标签数还取决于 padding 和被忽略位置。
- 专业：不能。应在相同 token 预算或透明的计算预算下，用无污染的留出数据与多类下游任务评测，并报告语言/领域切片、重复率和训练效率。

</details>

## 自测

1. 因果语言模型的目标 token 能看到它后面的真实 token 吗？为什么？
2. MLM 为什么只对选中的遮蔽位置计算主要预测损失？
3. Encoder–decoder 如何同时利用完整输入并生成目标文本？
4. 子词表示怎样缓解词表外词问题？它又带来什么取舍？
5. logits 为 $[B,T,V]$ 时，目标 token ID 的形状通常是什么？

<details>
<summary>核对要点</summary>

1. 不能。条件分布只依赖 $x_{<t}$，注意力实现必须屏蔽未来。
2. 未被遮蔽的位置通常直接出现在输入中，预测它们不能提供相同的恢复任务信号。
3. 编码器提供输入表示；自回归解码器逐位置生成目标。
4. 罕见词可拆成已知子词或字节；代价是切分可能不直观，且序列长度随切分方式变化。
5. 通常为 $[B,T]$，每个位置是一个词表类别的整数 ID。

</details>
